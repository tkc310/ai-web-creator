# プロンプト集

サイトのオーナーが Claude に送る文章です。（ ）の部分を書き換えて使います。

## はじめるとき

```
https://github.com/tkc310/ai-web-creator にあるスキル（skills フォルダ）を読み込んで、
私のサイト作りを手伝ってください。
読み込めたら、最初に、読み込んだスキルの版（CHANGELOG.md のいちばん新しい見出し）を教えてください。
私は IT に詳しくありません。
質問は選択肢をつけて、一度に4つまでにしてください。
```

## Claude Code に移ってから最初に送る文章

チャットでの相談の最後に、Claude がプロジェクトの指示の下書きと引き継ぎ文を作ります。サイトのプロジェクトを作って指示を貼り、プロジェクトの会話に引き継ぎ文をそのまま送ります（[使い方](../docs/how-to-use.md)）。引き継ぎ文の1行目は、スキルを取り込む指示です。消さずに送ってください。

チャットの最後に引き継ぎ文が出なかったときは、チャットで次のように頼みます。

```
Claude Code に移ります。プロジェクトの指示の下書きと、最初に送る引き継ぎ文を作ってください。
```

引き継ぎ文がない場合は、次の文章を使います。

```
最初に、curl -fsSL https://raw.githubusercontent.com/tkc310/ai-web-creator/main/skills/web-creator/references/skills-install.md
でスキルの取り込みの手順書を取得して読み、その「初回の手順」でスキルをこのリポジトリの skills/ に取り込んでください
（GitHub の API や、リポジトリをこの会話に追加する操作は使わないでください）。
取得できなければ、git clone --depth 1 https://github.com/tkc310/ai-web-creator /tmp/ai-web-creator-read で取得して同じファイルを読み、
どちらも失敗したら、推測で進めずに、スキルの zip を渡すよう私に頼んでください。取り込めたら、取り込んだ版を教えてください。
そのあと、skills/web-creator/SKILL.md に従ってサイトを作ってください。
チャットで相談した内容は次のとおりです。
（相談の内容を貼る）
```

## 今のサイトから引っ越すとき

```
今のサイト（URL）から引っ越したいです。今のサイトは（WordPress / STUDIO / ほかのサービス）で作っています。
検索順位や問い合わせが減らないように進めてください。
```

## デザインを選ぶとき

```
（B）の案で進めてください。（色は A のほうが好きです。）
```

## 要点だけ伝えて記事にしてもらうとき

```
お知らせを書いて公開してください。要点は次のとおりです。
・（年末年始は 12/29〜1/3 まで休業）
・（1/4 から通常営業）
・（休業中のお問い合わせは 1/4 以降に順番に返信）
公開する前に、プレビューを見せてください。
```

## 書いた文章を校正して載せてもらうとき

```
この文章を校正して、ブログに載せてください。直したところは一覧で教えてください。
（文章を貼る）
```

## 記事の原稿を書くとき（おすすめ）

Claude が原稿用のドキュメント（Claude ドキュメント）を作ってリンクを渡します。要点だけ書いて「書けました」と送ると、プレビューを見せてから公開します。

```
新しい記事の原稿を用意してください。
```

```
書けました。
```

## 記事の追加のしかたを教えてもらうとき

```
記事の追加を教えてください。
```

## 記事やお知らせを追加するとき

```
この Google ドキュメントの内容を、お知らせに載せてください。
公開する前に、プレビューを見せてください。
（ドキュメントのリンク）
```

## プレビューを見て直してもらうとき（おすすめ）

プレビューのページで、直したい文章や画像を選んでコメントを書き、Claude に送ります。場所を説明しなくて済むので、いちばん手軽です。コメントの例:

```
ここは「年末年始」ではなく「冬季休業」にしてください。
```

```
この写真を、きのう送った店の外観の写真に差し替えてください。
```

コメントを送っても返事がないときは、チャットで次のように頼みます。

```
プレビューのコメントを見て、直してください。
```

## お問い合わせフォームを付けたいとき

```
お問い合わせフォームを付けたいです。
どの方法がよいか、選択肢をつけて教えてください。
```

選び方は [お問い合わせフォームの作り方](../docs/forms.md) にあります。

## 直してほしいとき

```
（会社概要の住所）を（〇〇ビル3階）に直してください。
```

## 公開に失敗したとき

```
GitHub から公開失敗のお知らせが来ました。直して、原因を教えてください。
```

## 表示がおかしいとき（直前の変更を取り消す）

```
サイトの表示がおかしいです。直前の変更を取り消して、前の状態に戻してください。
```

## 独自ドメインにつないだ直後に、公開後の確認で失敗したとき

```
公開後の確認をもう一度してください。取り消す前に、数分おいてページが開くかを確かめてください。
```

## 見出しを変えたら、公開後の確認で失敗したとき

```
公開後の確認のリストを、今のページに合わせて直してください。
```

## 予定の日に公開する・公開をやめるとき

```
この記事を（11月1日の朝）に公開してください。それまでは公開しないでください。
```

```
（お知らせ「年末年始の休業」）の公開をやめてください。消さずに残しておいてください。
```

## 確認なしで公開してよいものを決めるとき

```
確認なしで公開してよい変更の種類を決めたいです。選択肢をつけて聞いて、SITE.md に書いてください。
```

数字（営業時間、価格、日付）、ページの部品、人が写っている写真の変更と、要点から作った下書きは、確認なしにした種類に当たっても、Claude が必ずプレビューを見せます。

## アクセス数を知りたいとき

```
今月どのくらい見られているか教えてください。よく見られたページも3つ教えてください。
```

## 検索や Google マップに載せたいとき

```
Google の検索に載るように、Search Console への登録とサイトマップの送信を、画面ごとに教えてください。
```

```
Google マップの店の情報（Google ビジネスプロフィール）に、新しいサイトの URL を載せる手順を教えてください。
```

## 自動の手入れを確かめたいとき

```
自動の手入れ（保守や振り返り）の設定と、次に動く日を教えてください。
```

## 担当者が代わるとき

```
サイトの担当者が代わります。引き継ぐものを一覧にして、手順を教えてください。
```

## わからないことがあるとき

```
（このサイトにかかっている費用）を、わかりやすく教えてください。
```

## 振り返ってほしいとき

```
最近の作業のログを振り返って、改善点をまとめてください。
直せるものは直して、確認が必要なものは選択肢をつけて聞いてください。
```

## 自分の環境が変わったとき

```
パソコンを（Windows）に買い替えました。
プロジェクトの指示の「作業の環境」を直してください。
```

## 別の会話で続きを頼むとき

サイトのプロジェクトを使っている場合は、プロジェクトの会話に書けば続きから進みます。プロジェクトを使っていない場合は、次の文章を使います。

```
（サイト名）のホームページの続きをお願いします。
GitHub の（リポジトリ名）にある SITE.md を最初に読んでから進めてください。
```
