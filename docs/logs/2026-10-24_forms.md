# 2026-10-24 お問い合わせフォームの選び方と導入方法

- きっかけ: フォームの作り方を比べた結果、基本は Google フォーム（リンクか埋め込み）、見た目にこだわる場合だけ Cloudflare Email Sending を Claude と対話しながら導入する方針に決めた
- 変えたファイル: docs/forms.md（新規）、skills/web-creator/references/forms.md（新規）、skills/web-creator/templates/forms/（新規: contact-handler.ts、astro-api-contact.ts、html-worker.ts、wrangler-contact.jsonc、contact-form.html）、references/hearing.md、references/build.md、references/stack-selection.md、SKILL.md、prompts/README.md、README.md

## やったこと

1. ヒアリングの「問い合わせの受け方」を4択にした（Google フォームのリンク / 埋め込み / 自前のフォーム / 置かない）
2. Google フォームの作り方、通知とスプレッドシートの設定、埋め込むときの注意（問い合わせページだけ、loading="lazy"）を書いた
3. 自前のフォームの手順を、人に任せる操作がどこに入るかが分かる形で書いた。選ぶ前に伝える4つのこと（手順の多さ、ベータ版、料金、要保守構成）を決めた
4. 自前のフォームのコードのひな形を作った。Origin、大きさ、必須項目、文字数、メールアドレスの形、隠し項目、Turnstile（ホスト名も）を確かめ、本文はテキストだけで送り、件名から改行を除く。送信内容は保存しない
5. formrun、Tally、Web3Forms、Formspree、Resend を番外編として紹介し、預け先が1つ増えることを注意として書いた

## 確認したこと（2026-10-24）

- Email Sending は Cloudflare の DNS を使うドメインが条件。送信用のレコードは cf-bounce のサブドメインに入り、受信用の MX は変えない。Email Routing は受信用の MX を置き換えるので、今のメールがあるドメインでは有効にしない（https://developers.cloudflare.com/email-service/configuration/domains/ 、https://developers.cloudflare.com/email-service/get-started/send-emails/）
- 料金: 確認済みの宛先への送信はどのプランでも無料とされている。一方で Email Sending は Workers Paid の機能とも書かれている。無料プランで使えるかは公式の説明だけでは判断できなかった（https://developers.cloudflare.com/email-service/platform/pricing/）
- Email Sending は2026年4月から公開ベータ（https://developers.cloudflare.com/changelog/product/email-service/）
- `env.EMAIL.send()` の項目名は `to`、`from`、`subject`、`text`、`html`、`replyTo` など（https://developers.cloudflare.com/email-service/api/send-emails/workers-api/）
- Astro 6 の @astrojs/cloudflare では `import { env } from "cloudflare:workers"` で環境変数を読む（https://v6.docs.astro.build/en/guides/integrations-guide/cloudflare）
- Turnstile は無料プランでも認証の回数に上限なし（https://developers.cloudflare.com/turnstile/plans/）
- contact-handler.ts は tsc --strict で型チェックが通った。Node.js で fetch と EMAIL を差し替え、正常、隠し項目、Origin 違い、必須項目、メールの形、文字数、Turnstile 失敗の7件を試し、想定どおりの戻り先になった。件名の改行は取り除かれた

## 確認できなかったこと

- Cloudflare の実際のアカウントでの Email Sending の登録、無料プランでの送信、届いたメールの迷惑メール判定
- Astro の実際のプロジェクトでのビルド（npm のレジストリに接続できない環境のため）
- `run_worker_first` を使った HTML だけのサイトでの動作
- `send_email` の接続で宛先を固定する設定の項目名（ドキュメントで見つけられなかったため、ひな形には入れていない）
