## やったこと

1. IMPROVEMENTS.md を、無いサイトでも作るようにした
   - 初回の取り込みの手順4で、CLAUDE.md と AGENTS.md と一緒に、templates/IMPROVEMENTS.md から logs/IMPROVEMENTS.md を置く（すでにあれば上書きしない）
   - 既存サイトのスキル更新、記事の更新、保守、振り返りでも、無ければ同じテンプレートから作る
   - 自動修正は、シェルでコピーせず、テンプレートの内容を logs/IMPROVEMENTS.md に書いてから未対応へ足す。テンプレートが読めなければ作らず、実行ログにだけ書く
2. ヒアリングの答えを、原文と要点に分けた
   - 引き継ぎ文に「ヒアリングの答え」（質問と選んだ答えを1行ずつ）を足し、Claude Code の初回に logs/YYYY-MM-DD_hearing.md として保存する。段階1を飛ばした場合は、聞き終わったときに保存する
   - SITE.md には要点だけを置く。「雰囲気」「更新の頻度」「載せてはいけない情報」と、振り返りで使う「オーナーの好み」を足した
   - 掲載してはいけない情報は、プレビューの前と、プレビューを省略する公開の前と、記事の本文を整えるときに照合する。当たれば除き、1行で伝える。欄が無ければ聞きに行かない
   - 原文は作業の前の読書に入れない。保管期間が来ても削除しない
3. 月次の振り返りの連絡に、種類「スキル」の未送信件数と、そのまま送れる Issue の下書きを添えるようにした
   - 未送信が1件以上のときだけ、そのために連絡する。0件でほかの確認もなければ連絡しない
   - 送るのは「送って」と返ったときだけ。返さなければ送らず、次の会話で聞き直さない
   - スケジュールタスクのときは確認待ちに1行残し、次の会話で伝えたら消す。下書きは振り返りのログに残す
   - 送り先の既定は GitHub の Issue にした。note は、オーナーがそう指定したときだけ
4. 作業前に読むログを、今回と同じ種類の新しいログ最大3件にした。種類はログ先頭の「種類」で分け、違う種類の本文は読まない。保守ログと記事更新のログも最大3件にした
   - すでに貼ってあるプロジェクトの指示に古い読み方（新しいログ3件）が残っていても、リポジトリの AGENTS.md を優先する1文を足した。貼り直しは頼まない。CLAUDE.md のひな形と、これから渡すプロジェクトの指示にも、同じ優先を1文で書いた
5. 実行ログの「依頼」を、訪問者や第三者の個人情報を除いた要約にした
6. 振り返りで、同じ好みや決まりが3回以上（今回のログと、未対応の「元のログ」に並んだファイル名）あれば、SITE.md に1行で昇格して項目を閉じる。理由があるものは「決めたことと理由」、好みは「オーナーの好み」。古いログは開かない
   - IMPROVEMENTS.md の「対応済み」は、90日を待たずにその月の要約へ移し、一覧には未対応と「スキルに報告したもの」を残す。実行ログの90日は変えない
