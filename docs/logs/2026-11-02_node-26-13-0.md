# 2026-11-02 Node.js を 26.13.0 に揃える

- きっかけ: オーナーからの直接の指示。このリポジトリで使う Node.js を 26.13.0（2026-10-28 リリースの LTS Lithium）に揃える
- 変えたファイル: skills/web-creator/templates/node-version.txt、skills/web-creator/templates/package-json-fields.md、skills/web-creator/references/versions.md、skills/web-creator/references/build.md、skills/web-creator/references/deploy-and-autofix.md、skills/runtime-update/SKILL.md、.node-version（新規）、CHANGELOG.md

## やったこと

1. サイトに置く Node.js の指定を、メジャー番号（`26`）から完全な版 `26.13.0` にした
   - templates/node-version.txt は、数字のない埋めて使うひな形だった。中身を `26.13.0` にし、そのまま `.node-version` として置く
   - package.json の `engines.node` は、これまでの `>=` の書き方のまま `>=26.13.0` にした
   - ワークフローは `node-version-file: .node-version` のまま（版の数字は `.node-version` の1か所）
2. 「メジャー番号だけを書く」という手順をやめ、runtime-update が上げるときも完全な版を書くようにした
3. 配布元自身は Node.js の指定が無く、`scripts/run_lighthouse.sh` と検証用の `.mjs` が node を使うため、直下に `.node-version`（`26.13.0`）を足した

## 確認したこと

- Node.js 26.13.0 は 2026-10-28 の LTS「Lithium」。26 系は同日に LTS になり、サポートは 2029-04-30 まで。2026-11-02 の index.tab で 26 系の最新は 26.13.0（27 は alpha）: https://nodejs.org/en/blog/release/v26.13.0 、https://nodejs.org/download/release/index.tab 、https://raw.githubusercontent.com/nodejs/Release/main/schedule.json
- `.github/scripts/check_skills.py` と `skills/web-creator/scripts/check_text.py --no-markup`（変えたファイル）

## 確認できなかったこと

- サイトのリポジトリで、`26.13.0` の Node.js を使って `pnpm install` と `pnpm run build` が通るかは、この配布元にはサイトのプロジェクトが無いため試していない

## 次回の改善点

- 作者が次のタグを打つとき、`MANIFEST.txt` を作り直す（この変更ではタグを打たない。main に入れたあとの check-skills は、一覧の SHA-256 が合うまで失敗する）
- README と prompts は「最新の LTS」とだけ書いて版の番号が無いので、変えていない。番号は versions.md にだけ置く決まりのまま
