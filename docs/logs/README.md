# 改善ログ

このリポジトリのスキル、プロンプト、ガイドを改善したときの記録です。何を見て、何を変え、何が残ったかを残し、次の改善の出発点にします。

## 改善ループ

1. 材料を集める: Issue、サイトのリポジトリの作業ログにある「改善メモ」（オーナーの了承を得て、個人情報とサイトの情報を除いたもの）、エージェント自身が作業中に気づいたこと
2. 直す前に読む: このフォルダの新しいログから5件ほど読み、「次回の改善点」と「確認できなかったこと」を拾う
3. 直す: スキル、prompts/、README.md、docs/ の説明が食い違わないように変える
4. 記録する: このフォルダにログを書き、CHANGELOG.md にも1行で書く
5. 次につなぐ: 終わらなかったことは、ログの「次回の改善点」に書く。大きいものは Issue にする

## 書くとき

- スキル、テンプレート、スクリプト、prompts/、docs/、README.md を変えたとき
- 調べた結果、変えないと決めたとき（理由を残すと、同じ調査を繰り返さずに済む）

## 書かないこと

- 特定のサイト、会社、個人の情報（URL、名前、問い合わせ先など）
- パスワード、API トークン、認証コード
- このリポジトリの外で書いている記事や原稿の修正の記録

## ファイル名と書き方

- ファイル名は `YYYY-MM-DD_内容.md`（例: `2026-10-24_improvement-logs.md`）。同じ日に複数あるときは内容で分ける
- 書き方は [_template.md](_template.md) に従う
- 料金や仕様を確認した場合は、確認した日と出典の URL を書く
