# スキルとプロンプトの使い方

このリポジトリのスキルを Claude に読ませて、サイトを作り、公開し、運用するまでの使い方です。Claude のアカウントがまだない場合は、先に [Claude のアカウント登録ガイド](claude-account.md) を済ませてください。

## 全体の流れ

作業する場所は2つあります。

| 段階 | 作業する場所 | やること |
|---|---|---|
| 1. 相談と準備 | Claude のチャット（claude.ai、デスクトップアプリ、スマートフォンのアプリ） | 要望のヒアリング、作り方の決定、GitHub と Cloudflare のアカウント作成 |
| 2. 制作と運用 | Claude Code（claude.ai/code、デスクトップアプリの「Code」）のサイトのプロジェクト | サイトの制作、公開、更新、保守、振り返り |

Claude Code はクラウド上の作業環境で動き、GitHub のリポジトリに直接保存します。そのため、GitHub のアカウントができてから使います。段階1から2に移るときは、Claude が移り方と、最初に送る文章を案内します。

## 使うモデル

モデルは Claude Opus 5.5 を使います。チャットでも Claude Code でも、モデルの一覧から Opus 5.5 を選んでください。

考える深さ（effort）は、作業の種類でスキルが使い分けます。計画とデザインは high（じっくり考える）、制作・更新・保守は medium（標準）です。スキルが働かない場面で Claude から切り替えを頼まれたら、モデルの選択画面で設定してください。

## 段階1: チャットで相談する

Claude のチャットで、次の文章を送ります。

```
GitHub の tkc310/ai-web-creator にあるスキル（skills フォルダ）を読み込んで、
私のサイト作りを手伝ってください。
私は IT に詳しくありません。
質問は選択肢をつけて、一度に5つまでにしてください。
```

Claude が選択肢つきの質問をするので、答えていきます。ロゴ、写真、会社案内の PDF があれば、このときに添付します。

続いて、GitHub と Cloudflare のアカウントを作ります。

- 登録や設定の方法は、Claude が画面ごとに対話しながら教えます。分からない画面が出たら、スクリーンショットを貼って聞けます
- Claude にブラウザの操作を任せられる環境（Claude in Chrome、デスクトップアプリ）では、Claude が画面を進めます
- パスワードの入力、2段階認証、支払いと規約への同意、秘密の鍵の貼り付けは、必ずあなたが行います

相談の最後に、Claude が次の2つを作ります。

- プロジェクトの指示: あなたの使っている環境（パソコン、ブラウザ、原稿の置き場所など）と、作業の決まり。これを読んでから Claude が作業するので、毎回説明し直す必要がなくなります
- 引き継ぎ文: 要望や決めたことのまとめ。Claude Code に移ってから最初に送ります

## 段階2: Claude Code で作る

1. GitHub に、サイト用の空の非公開リポジトリを作る（作り方は Claude が案内します）
2. このリポジトリ（tkc310/ai-web-creator）のページで、右上の「Fork」→「Create fork」を押し、あなたの GitHub に写しを作る。Claude のプロジェクトには、あなたが書き込めるリポジトリしか追加できないためです
3. Claude の GitHub アプリをインストールし、サイトのリポジトリと、手順2の写しの2つを選ぶ（[アカウント登録ガイド](claude-account.md) の「4. GitHub とつなぐ」）
4. claude.ai/code を開き、左のメニューの「Projects」から「New project」を押す
5. Name に「（サイト名）のサイト」と入れ、Context の「Add」から「サイトのリポジトリ」と「あなたのユーザー名/ai-web-creator」（手順2の写し）の2つを選んで、「Create project」を押す
6. プロジェクトの歯車のボタンから「Project settings」→「Memory」→「Project instructions」を開き、段階1で Claude が作ったプロジェクトの指示を貼って保存する
7. プロジェクトの会話に、段階1の最後に Claude が作った引き継ぎ文を送る

写しは、このリポジトリの更新を自動では受け取りません。Claude が月1回の振り返りで更新を確かめて知らせるので、そのときは写しのページで「Sync fork」→「Update branch」を押します。

Claude Code のプロジェクトは、執筆時点でベータ版です。Pro と Max プランで順に使えるようになっていて、左のメニュー（または「More」の中）に「Projects」がない場合は、まだ使えません。その場合は手順4〜7の代わりに、claude.ai/code でリポジトリの選択から「サイトのリポジトリ」と「手順2の写し」の2つを選び、引き継ぎ文を送ります。プロジェクトの指示の内容は、Claude が SITE.md に書いておきます。

あとは、Claude がデザインの案を見せる、公開前のチェック結果を伝える、取り消しにくい操作の前に確認する、といった場面で返事をするだけです。

デザインの案や、公開前の変更は、Claude がプレビューのページ（アーティファクト）を作って見せます。チャットに出るカードを開くと、スマホと PC の見え方を切り替えて確認できます。社内の人にも見てもらいたい場合は、アーティファクトの共有メニューから共有します。

直したいところがあれば、プレビューのページの上で、その文章や画像を選んでコメントを書き、Claude に送ってください。Claude が直して、同じページのプレビューを新しくし、コメントに返事をします。場所を言葉で説明しなくて済むので、いちばん手間がかからず、伝え違いも起きにくい方法です。チャットで「2段落目の『〜』を『〜』に」のように伝えても直せます。

## 公開したあと

サイトの更新や質問は、サイトのプロジェクトの会話に書くだけです。スマートフォンのアプリからも書けます。Claude が作業ごとに担当を立てて進め、終わったら会話で知らせます。

プロジェクトを使っていない場合は、Claude Code でサイトのリポジトリを選んで頼みます。毎回、最初に次の一文を入れると確実です。

```
（サイト名）のサイトの作業です。SITE.md を最初に読んでから進めてください。
```

パソコンを買い替えた、担当者が変わった、原稿の置き場所が変わった、といったときは「プロジェクトの指示を直して」と頼みます。

頼み方の例は [プロンプト集](../prompts/README.md) にあります。

- お知らせやブログの追加: 原稿をチャットに書くか、Google ドキュメントのリンクを貼る
- 文章や写真の修正: 「ここをこう直して」と頼む
- 脆弱性のニュースを見かけたとき: 記事のリンクを貼って「このサイトに関係あるか確認して」と頼む

## 定期的な保守

一部のページをその場で処理する構成や、EmDash を使う構成の場合は、公開時に Claude がスケジュールタスク（旧称: ルーティン）を設定します。毎月1日と15日に、部品の更新を確認して反映します。設定の内容は [site-maintenance](../skills/site-maintenance/SKILL.md) にあります。

## 作業の記録と振り返り

Claude が動くたびに、サイトのリポジトリの logs/ に記録（実行ログ）が残ります。あなたが頼んだ作業だけでなく、公開の自動修正や定期的な保守の記録も残ります。

- 次から気をつけたほうがよいこと（あなたに直された言い回し、つまずいた手順など）は、改善点の一覧（logs/IMPROVEMENTS.md）にまとまり、次の作業の前に Claude が読みます
- 月に1回、Claude が記録を振り返り、改善点を整理して直します。確認が必要なものだけ、あなたに聞きます
- 90日を過ぎた記録は、月ごとの要約にまとめて元のファイルを消します。消したファイルも GitHub の履歴から戻せます。残しておきたい場合は「ログは消さないで」と頼んでください
- 振り返りは、要保守構成のサイトでは毎月1日の保守と一緒に行います。それ以外のサイトでは、月1回の振り返りのスケジュールタスクを作るかどうかを、公開するときに Claude が聞きます（Claude の利用量を少し使います）

## スキルを Claude に登録して使う（任意）

上の方法では、毎回 GitHub のスキルを読み込ませます。よく使う場合は、スキルを Claude に登録しておくこともできます。

1. このリポジトリの skills/ の中から、使うスキルのフォルダ（例: web-creator）を、フォルダごと ZIP にする
2. claude.ai の「Customize」→「Skills」で「+」→「Create skill」→「Upload a skill」を選び、ZIP をアップロードする
3. アップロードしたスキルをオンにする

スキルを使うには、設定の「Capabilities」で「Code execution and file creation」がオンになっている必要があります。スキルを更新したときは、もう一度アップロードします。
