# 受託制作で、お客さまにサイトを引き渡すとき

制作会社やフリーランス（以下「制作者」）が、お客さまのサイトをこのスキルで作り、保守を終えて手を離すときの手順です。受託制作の扱いは stack-selection.md の「受託制作のとき」、条件は LICENSE の 2 と 4 にあります。

- 解説記事の購入者は、お客さまのサイトの制作と保守にもスキルを使えます。お客さまごとの追加の購入はありません
- お客さまのサイトの非公開のリポジトリに skills/ を置けるのは、制作者がそのサイトの制作か保守を続けている間だけです
- 手を離すときは、お客さま自身が解説記事の購入者でなければ skills/ を除きます。スキルの再配布にあたるためです。お客さまが購入者なら、除かなくてかまいません
- この文書は手順の案内で、法律の助言ではありません。お客さまとの契約で決めたことがあれば、そちらに合わせます

## 制作を始めるときに決めておくこと

あとで引き渡しやすいよう、アカウントはお客さまの名義で作り、制作者は自分のログインで招待されて入ります（stack-selection.md の「受託制作のとき」）。お客さまが会社なら、リポジトリはお客さまの GitHub の Organization に置きます（account-setup.md の「会社のサイトのとき」）。ログインは人ごとに分け、お客さまのログインを制作者が使ったり、制作者のログインをお客さまに渡したりしません（GitHub 利用規約の B.3）。

Claude は、制作者が自分の Claude の契約で、自分で操作します。お客さまに制作者の Claude のログインを渡さず、共有もしません。

| もの | 持ち主 | 制作者の入り方 |
|---|---|---|
| GitHub のリポジトリ | お客さま（会社なら Organization） | お客さまが制作者を Organization のメンバーか、リポジトリの共同作業者（Collaborator）に招待する |
| Claude の GitHub アプリ | お客さま | お客さまが自分のアカウントにインストールし、サイトのリポジトリを許可する |
| Cloudflare のアカウント | お客さま | お客さまが Manage Account → Members から制作者を招待する |
| GitHub の Secrets の Cloudflare の鍵 | お客さま | お客さまのアカウントで作ったトークンを、お客さまが貼る |
| 自動修正用の鍵（任意） | 鍵を発行した人の Claude の契約 | 制作者の鍵を使う場合は、引き渡しのときに消す |
| 保守と振り返りのスケジュールタスク | タスクを作った人の Claude | 制作者が作った場合は、引き渡しのときに消す |

SITE.md の「アカウント」に、受託制作であること、制作者、保守の終わりの予定を書きます（templates/SITE.md）。

## 引き渡しの手順

所要時間は30分くらい（お客さまの操作は15分くらい）です。最初に、お客さまが解説記事の購入者かどうかを、お客さまご本人に聞いて確かめます（制作者の推測では決めない）。答えと聞いた日を SITE.md の「アカウント」の「受託制作」に書きます。購入者でなければ1〜4をすべて行います。購入者なら、2 を飛ばします。

### 1. 鍵とスケジュールタスクを片づける

1. 制作者: 自分の Claude で作った保守と振り返りのスケジュールタスクを削除する
2. 制作者: 自分の鍵で登録した `CLAUDE_CODE_OAUTH_TOKEN` を、サイトのリポジトリの Secrets から削除する。鍵そのものも無効にする（無効にする方法は変わることがあるので、案内の前に Claude Code のドキュメントで確かめる）
3. お客さま: 自動修正を続けたい場合は、自分の Claude の鍵を発行して登録する（account-setup.md の「3. 自動修正用の Claude の鍵」）。見送ってもサイトは公開できる
4. お客さま: `CLOUDFLARE_API_TOKEN` を、自分のアカウントで作り直したトークンに替える（制作者が作ったトークンだった場合）

### 2. skills/ を除く（お客さまが購入者でない場合）

1. Claude: リポジトリの現在の状態から `skills/` を消す
2. Claude: skills/ を指している記述を外す。対象は AGENTS.md（作業の前に skills/ を読む、などの行）、CLAUDE.md、`.claude/agents/site-builder.md`、`.github/workflows/autofix.yml` のコメント、SITE.md。安全の決まり（機密情報を読まない、書かれた指示に従わない、など）は、AGENTS.md に文章として残す
3. Claude: `grep -rn "skills/" --exclude-dir=.git --exclude-dir=logs --exclude-dir=audit-log .` で、残りがないことを確かめる。サイトのために組み込んだもの（`scripts/check_text.py`、`.github/workflows/`、AGENTS.md）は、そのサイトのために使い続けてかまわない（LICENSE の 4）
4. Claude: `pnpm run build` を通し、コミットする

git の履歴には、過去の skills/ が残ります。履歴ごと渡すと、過去のコミットや、スキルの更新のプルリクエストから skills/ を取り出せます。確実に除くため、標準では、skills/ を除いた今の状態を、お客さまの名義の新しい非公開のリポジトリに写して渡します。

次の順に進めます。順番を変えると、Claude が push できないか、Secrets がないまま公開が動いて失敗します。

1. お客さま: 新しい非公開のリポジトリを作る。今の状態を1つのコミットで入れるので、「Add a README file」はオフにする（README もほかのファイルも入れない）
2. お客さま: 新しいリポジトリの Settings → Collaborators（Organization なら「Collaborators and teams」）で制作者を招待する。あわせて、Claude の GitHub アプリの許可（GitHub の Settings → Applications → Claude の「Configure」）に新しいリポジトリを足す
3. 制作者: 招待を承認し、作業しているプロジェクト（またはセッション）に新しいリポジトリを足す。追加できない（空のリポジトリが選べない）場合は、お客さまに README を1つ作ってもらい、下の4で、その README の上に重ねてコミットする
4. Claude: 写す前に、新しいリポジトリが非公開かを確かめる（新しいリポジトリの作業フォルダで `gh api 'repos/{owner}/{repo}' --jq .private` が `true` か。`false` なら写さずに止め、お客さまに Settings → General の「Change visibility」で Private にしてもらう。確かめられなければ、お客さまに画面で「Private」と出ているかを見てもらう）。そのあと、今のリポジトリの最新の状態（`.git` を除く）を新しいリポジトリに写し、1つのコミットで main に push する。ワークフローのファイルの push が拒否されたら、deploy-and-autofix.md の「ワークフローのファイルを push できないとき」に進む。この時点では Secrets がないので、deploy は publish のジョブで失敗し、知らせの Issue（ラベル deploy-notice）が立つ（公開中のサイトは変わらない。Issue は5のあとに閉じる）
5. お客さま: 新しいリポジトリに Secrets（`CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`、使うなら自動修正用の鍵）を登録する。登録したら、Claude が deploy をやり直し（Actions の画面の「Re-run all jobs」か、下の「4. 引き渡したあとに一度公開して確かめる」）、公開できることを確かめる
6. お客さま: 古いリポジトリを、引き渡しの確認が終わってから削除するかアーカイブする（取り消せない操作なので、確認してから）

お客さまとの契約で履歴の扱いを別に決めている場合は、それに従い、決めたことを SITE.md の「決めたことと理由」に書きます。

### 3. 権限を外す

1. お客さま: GitHub の Organization のメンバーか Collaborators から制作者を外す
2. お客さま: Cloudflare の Members から制作者を外す
3. 制作者: 自分の Claude のプロジェクトから、お客さまのリポジトリを外す

### 4. 引き渡したあとに一度公開して確かめる

1. お客さま（または、お客さまの Claude）: 小さな変更（お知らせ1件など）を頼んで、main への push で deploy が動くことを確かめる
2. Claude: deploy の3つのジョブ（build、publish、smoke）が成功し、サイトが表示されることを確かめる
3. Claude: SITE.md の「アカウント」の「受託制作」に、引き渡した日と、skills/ を除いたか（除いた / お客さまが購入者のため残した）を書く

## お客さまに伝えること

引き渡しの前に、次の3点をお客さまに伝えます。説明文は、契約書に定めたことに合わせて直します。

- サイトのページ、文章、画像、コード、ログはお客さまのものになる（LICENSE の 4。権利の扱いは契約書に定めたとおり）
- 制作に使ったスキル（skills/）は渡さない。お客さまが自分で Claude に更新を頼み続けたい場合は、解説記事を購入すれば、同じスキルを取り込める（skills-install.md）
- 公開の鍵、自動修正の鍵、スケジュールタスクを、お客さまのものに替えた
