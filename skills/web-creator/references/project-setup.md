# Claude のプロジェクトを作る

制作と運用は、サイトごとに作る Claude Code の「プロジェクト」の中で進めます。オーナーの作業の進み具合や使っている環境を、毎回説明し直さなくて済むようにするためです。

## プロジェクトで何が変わるか

プロジェクトは、1つのサイトについての会話を1か所にまとめる場所です。オーナーはプロジェクトの会話に頼みごとを書くだけで、Claude が作業ごとにスレッド（クラウドで動く Claude Code のセッション）を立てて進めます。

| 置き場所 | 中身 | 書く人 |
|---|---|---|
| プロジェクトの指示（Project instructions） | このサイトとオーナーの説明、オーナーの環境、作業の決まり。新しいスレッドはすべて、これを読んでから始まる（16,000字まで） | 段階1の Claude が下書きし、オーナーが貼る。変更は Claude に頼めば直せる |
| プロジェクトのメモリ | 作業の中で決まったこと、気をつけること。Claude が自分で書き足す | Claude |
| サイトのリポジトリの SITE.md、CLAUDE.md、logs/ | サイトの技術、決めたことと理由、作業ログ、改善点 | Claude |

役割を分けて、同じことを2か所に書かないようにします。

- プロジェクトの指示: 「誰と、どう作業するか」（オーナーの環境、連絡のしかた、確認が必要な操作）
- SITE.md: 「このサイトは何か」（技術、アカウントの持ち主、更新方法、決めたこと）。プロジェクトが使えない環境や、ほかのエージェントに引き継ぐときにも、ここを見れば分かるようにする
- logs/: 「何をして、何が起きたか」（references/run-logs.md）

## 使える条件

- Claude Code のプロジェクトは、2026年10月時点でベータ版です。Pro と Max プランで順に使えるようになっていて、Team と Enterprise プランではまだ使えません
- claude.ai/code の左のメニュー（または「More」の中）に「Projects」がなければ、まだ使えません。その場合は「プロジェクトが使えないとき」に従います
- 使えるかどうかと手順は変わりやすいので、案内する前に Claude Code のドキュメント（Projects のページ）で確認します

## 作る手順（段階1の終わりに行う）

GitHub のアカウント、サイト用の非公開リポジトリ、Claude の GitHub アプリのインストールが済んでから行います（account-setup.md）。所要時間は10分くらいです。

プロジェクトに追加できるのは、オーナーの GitHub アカウントで書き込めて、Claude の GitHub アプリを入れたリポジトリだけです。追加するのはサイトのリポジトリ1つだけで、スキルはそのリポジトリの `skills/` に取り込みます（skills-install.md）。プロジェクトに入れたリポジトリには、そのプロジェクトのスレッドから書き込めます。入れていないリポジトリには、GitHub アプリで許可していても書き込めません（account-setup.md の「Claude がリポジトリに書き込むための2つの許可」）。

1. 段階1の Claude が、プロジェクトの指示の下書きを templates/project-instructions.md から作る（ヒアリングの答えと、hearing.md の「作業の環境」の答えを埋める）
2. オーナー: claude.ai/code を開き、左のメニューの「Projects」から「New project」を押す
3. オーナー: 次のとおり入力して「Create project」を押す
   - Name: `<サイト名> のサイト`
   - Goal: `<サイト名> のサイトを公開し、更新と保守を続ける`
   - Context: 「Add」から、サイトのリポジトリ（例: `<owner>/<repo>`）を選ぶ。一覧に出てこない場合は、Claude の GitHub アプリにそのリポジトリを許可していないので、許可を追加してから開き直してもらう
4. オーナー: プロジェクトの歯車のボタンから「Project settings」→「Memory」→「Project instructions」を開き、手順1の下書きを貼って保存する
5. オーナー: プロジェクトの会話に、段階1の Claude が作った引き継ぎ文を送る

プロジェクトを作った直後に、Claude が設定の提案（Setup recommendations）を出すことがあります。サイトに関係のないリポジトリやスケジュールタスクが含まれていたら、オフにしてもらいます。

## スキルの読み込み

クラウドのスレッドは、リポジトリの `.claude/skills/` にあるスキルを読み込みません。読み込むのは、claude.ai のアカウントでオンにしたスキルと、各リポジトリの CLAUDE.md です。そのため、スキル一式をサイトのリポジトリの `skills/` に取り込み（skills-install.md）、サイトの CLAUDE.md（templates/AGENTS.md）に「作業の前に skills/ の該当する SKILL.md を読む」と書きます。プロジェクトの指示にも同じことを書きます（templates/project-instructions.md）。

新しい版への更新は、月1回の振り返りで確かめ、プルリクエストでオーナーに確認します（skills-install.md の「新しい版への更新」）。

## 公開したあと

- オーナーには「サイトのことは、このプロジェクトの会話に書けば伝わります」と伝える。スマートフォンのアプリからも書ける
- オーナーの環境が変わったら（パソコンを買い替えた、担当者が変わった、原稿の置き場所が変わった）、プロジェクトの指示を直す。オーナーに頼まれたら Claude が直す
- オーナーが何度も同じ指摘をしたら、プロジェクトのメモリに残すか、プロジェクトの指示に足す。サイトの技術に関わることは SITE.md に書く
- 保守ルーティン（site-maintenance）や振り返り（site-review）のスケジュールタスクは、プロジェクトの中から作る。プロジェクトの「Scheduled tasks」に並ぶので、オーナーが見つけやすい

## プロジェクトが使えないとき

claude.ai/code でサイトのリポジトリを選んで新しいセッションを始めます。スキルはサイトのリポジトリの `skills/` にあるので、ほかのリポジトリは要りません。プロジェクトの指示の代わりに、SITE.md の「作業の環境」に同じ内容を書き、オーナーには毎回次の一文から頼んでもらいます。

```
（サイト名）のサイトの作業です。SITE.md を最初に読んでから進めてください。
```

あとからプロジェクトが使えるようになったら、SITE.md の「作業の環境」からプロジェクトの指示を作り、移ります。

## 秘密情報

プロジェクトの指示、メモリ、ライブラリには、パスワード、APIトークン、認証コードを書きません。オーナーの個人の連絡先（携帯電話の番号、自宅の住所）も書きません。
