# 記事の追加チュートリアル（公開後）

お知らせ、ブログ、記事のあるサイトが一通り完成して公開できたら、オーナーと一緒に1本目の記事を追加します。オーナーが「原稿を書く → プレビューで確かめる → OK と返す → 公開される」の流れを一度体験し、次から一人で頼めるようにするためです。

## 対象と時期

- 対象: お知らせ、ブログ、コラムなど、公開後に記事を足していくサイト（多くは Astro。EmDash も含む）。1ページの LP など、記事のないサイトでは行わない
- 時期: 全ページの公開と、公開後の表示の確認が終わったあと（SKILL.md の「進め方の全体像」の 7）。要保守構成なら保守の設定の前後どちらでもよい
- オーナーに「最初の記事を一緒に追加してみませんか（10分ほど）」と聞き、「今やる / あとでやる / やらない」から選んでもらう。「あとで」なら、オーナーが「記事の追加を教えて」と頼んだときに行う
- 選んだ結果と、終わったかどうかを SITE.md の「更新の方法」の「記事の追加チュートリアル」に書く

## 原稿の置き場所を決める

1. SITE.md の「オーナーが原稿を置く場所」と、プロジェクトの指示に原稿の置き場所が書いてあれば、それに従う（Google ドキュメント、チャットなど）
2. 指定がなければ Claude ドキュメントを使う。Claude の中で書けて、リンク1つで Claude が読み取れるため、オーナーが新しい道具を覚えずに済む
3. Claude ドキュメントのツール（Docs）が使えない環境では、チャットに原稿を書いてもらう。Claude 以外のエージェントでの代わりは docs/other-agents.md

## 手順

### 1. 原稿のドキュメントを用意する（エージェント）

site-content-update スキルの templates/article-draft.md のひな形で Claude ドキュメントを1つ作り、リンクをオーナーに渡します。

このチュートリアルは、site-content-update の「標準の流れ」を、オーナーと一緒に一度通すものです。手順の2〜5は、標準の流れの2〜5と同じです。

1本目の題材は、オーナーに決めてもらいます。思いつかない場合は、サイトの公開のお知らせ（「ホームページを開設しました」）をすすめます。すでに同じお知らせがある場合は、最近の出来事や、よく聞かれる質問への答えをすすめます。

### 2. 原稿を書いてもらう（オーナー）

オーナーに次の3つを伝えます。

- ドキュメントを開いて、要点だけでも書けばよい（文章は Claude が整える）
- 書けたら、チャットで「書けました」と送る
- 写真は、ドキュメントに貼るか、チャットに添付する

### 3. 原稿を読み取って記事にする（エージェント）

site-content-update スキルの手順1〜6に従います。

- 原稿は Docs のツールで読み取る。写真をドキュメントから取り出せない場合は、チャットへの添付を頼む
- 原稿の汚染と機密情報を scripts/check_text.py で調べる（security-rules.md）
- 原稿の種類（要点 / 校正あり / そのまま）を判断して、本文を整える。チュートリアルでは、要点から作った下書きでも、そのままの原稿でも、必ずプレビューを見せる
- 写真は scripts/optimize_images.py で最適化する
- ビルドを通す

### 4. プレビューで確かめてもらう（エージェント → オーナー）

記事のページを `make_preview.py --comment` で HTML にまとめ、アーティファクトとして公開します（references/preview.md）。SITE.md のプレビュー用のアーティファクトがあれば、そこに公開し直します。

オーナーには次のように頼みます。

1. カードを開いて、記事の見え方を確かめる
2. 直したいところは、その文章や写真を選んでコメントを書き、Claude に送る
3. 直しがなければ、チャットで「OK」と返す

コメントを受けたら、preview.md の「コメントで直してもらう」の流れで直し、同じアーティファクトに公開し直します。チュートリアルでは、コメントの使い方を体験してもらうため、直しがない場合も「次からは、直したいところをこうして伝えられます」と一文で添えます。

### 5. 公開する（エージェント）

オーナーの「OK」を受けてから、main に入れて公開します（deploy-and-autofix.md）。

- 公開が終わったら、本番の記事の URL を開いて表示を確かめる
- 公開に失敗した場合は、自動修正（autofix）の結果を待つか、原因を直して公開し直す。オーナーには「公開に少し時間がかかっています。直して公開し直します」とだけ伝える
- オーナーに記事の URL を伝える

### 6. 振り返って記録する（エージェント）

オーナーに、次からの頼み方を3行で伝えます。

```
次からは、チャットで「新しい記事の原稿を用意して」と送ってください。
同じ形のドキュメントを作ってお渡しします。書けたら「書けました」と送るだけです。
要点をチャットに書いて「記事にして」と頼むこともできます。
```

- SITE.md の「更新の方法」に、原稿の置き場所（Claude ドキュメント、など）と、チュートリアルが終わった日を書く
- オーナーがつまずいたところ（ドキュメントの開き方、コメントの送り方など）を実行ログの改善メモに書く（run-logs.md）

## 2本目からの流れ

オーナーに「新しい記事の原稿を用意して」と頼まれたら、site-content-update スキルの「標準の流れ」で進めます。
