# 監査ログ（変更の記録）

サイトのリポジトリに、記事・お知らせ・サイトを「いつ、だれの依頼で、何を変えたか」の記録を残します。実行ログ（run-logs.md）とは目的が違うため、置き場所と扱いを分けます。

| | 実行ログ（logs/） | 監査ログ（audit-log/） |
|---|---|---|
| 目的 | 改善ループ。つまずいたことを次に生かす | 変更の記録。あとから「いつ何を変えたか」をたどる |
| 書くとき | エージェントが動くたび（質問だけでも書く） | 公開する内容を変えたときだけ |
| 単位 | 1回の実行につき1ファイル | 1日につき1ファイル。同じ日の変更は追記する |
| 整理 | site-review が90日で要約して削除する | 要約も削除もしない |

## 置き場所

```
audit-log/
├── 2026/
│   ├── 2026-11-02.md
│   └── 2026-11-15.md
└── 2027/
    └── 2027-01-08.md
```

- 年ごとのディレクトリ（`audit-log/YYYY/`）に、日ごとの Markdown（`YYYY-MM-DD.md`）を置きます
- 日付は日本時間（SITE.md でほかのタイムゾーンを決めていればそれ）で区切ります
- その日のファイルがなければ templates/audit-log.md から作り、あれば末尾に追記します。過去の記録は書き換えません。間違えた場合は、訂正の記録を追記します

## 記録する変更

| 種類 | 例 | 書く人 |
|---|---|---|
| 記事の追加 / 記事の修正 / 記事の非公開 | ブログ、コラムの公開、誤字の修正、`draft: true` にした | site-content-update |
| お知らせの追加 / お知らせの修正 / お知らせの非公開 | 休業日のお知らせ | site-content-update |
| サイトの修正 | 固定ページの文言や画像の差し替え、デザインやページ構成の変更、機能の追加・変更、リダイレクトの追加 | web-creator、site-content-update |
| 自動修正 | 公開の失敗を直した変更 | autofix ワークフロー |
| 保守 | 依存パッケージ、Node.js、`compatibility_date` の更新 | site-maintenance、runtime-update |

質問に答えただけ、プレビューを作っただけで公開していない、ログや SITE.md だけを直した、という場合は書きません。

## 書き方

1件の変更につき1つの見出しを書きます（templates/audit-log.md）。

- 時刻: 公開した時刻（HH:MM）
- 種類: 上の表の種類
- 対象: ページの URL（パス）と、変えたファイル
- 内容: 何を変えたかを1〜3行で。記事ならタイトル
- 依頼: オーナーの依頼 / 自動修正 / 保守ルーティン。オーナーの依頼なら、依頼の要約
- 確認: プレビューでオーナーが了承 / SITE.md で「確認なしでよい」とされた種類 / 自動（オーナーの確認なし）
- セキュリティ監査: 行った場合は件数と対応（security-audit.md）。行わない種類の変更なら「対象外」

## 書くタイミング

- 変更と同じコミットに入れます。コミットの履歴から、記録と実際の変更をたどれるようにするためです
- 公開に失敗して autofix が直した場合は、autofix が「自動修正」の記録を追記します
- 公開を取りやめた変更は、記録から消さずに「取りやめ」の記録を追記します

## 書かないこと

- パスワード、APIトークン、認証コード、Secrets の値
- 問い合わせをくれた人の名前や連絡先など、訪問者の個人情報
- 原稿の本文（タイトルと要約だけにする）

コミットの前に scripts/check_text.py で調べるファイルに、監査ログも含めます。
