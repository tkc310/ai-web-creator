# ヒアリング

サイトの目的と運用の仕方を、オーナーが選ぶだけで答えられる形で聞きます。聞いた内容は `SITE.md` の「概要」に書き残します。

## 1回目（必須・5問）

| # | 質問 | 選択肢の例 | 何に使うか |
|---|---|---|---|
| 1 | サイトで一番してほしいことは？ | 問い合わせ / 来店・予約 / 採用応募 / 商品やサービスを知ってもらう / 記事を読んでもらう | トップページの構成と、目立たせるボタン |
| 2 | 見てほしい人は？ | 取引先の担当者 / 近所のお客さん / 求職者 / 自由記述 | 文章の口調、デザインの方向 |
| 3 | 必要なページは？（複数選択） | トップ / 会社概要 / サービス / お知らせ / ブログ / 採用 / お問い合わせ / 1ページで十分 | 技術の選定、ページ構成 |
| 4 | 公開後、どのくらい更新しますか？ | ほぼしない / 月に数回 / 週に数回以上 / 毎日、複数人で | 技術の選定 |
| 5 | 今サイトはありますか？ | ない / CMS（WordPress など）/ ノーコードのサイト作成サービス / その他 | 引っ越しの有無（migration.md） |

## 2回目（1回目の答えを見て必要なものだけ）

- 雰囲気: 参考にしたいサイトのURL、または「信頼感」「親しみ」「高級感」「にぎやか」から選ぶ
- 素材: ロゴ、写真、会社案内のPDF、パンフレットがあれば添付してもらう。なければ「写真なしでも成り立つデザインにする」と伝える
- ドメイン: 持っているか（example.co.jp など）。持っていなければ取得は後で一緒にやると伝える
- 問い合わせの受け方: メールで受けたい / Googleフォームで受けたい / 電話番号を載せるだけでよい
- 掲載してはいけない情報: 個人の住所、未発表の情報など

## 対象外の要望が出たとき

ネットショップ、決済、会員機能、予約システムの自作などが必要と分かったら、SKILL.md の「対応しないもの」に従い、その場で伝えます。サイトの残りの部分は進めてよいかを確認します。

## 聞かないこと

- 使いたい技術、サーバー、CMS の名前（エージェントが決める）
- 予算の細目（Claude の利用料と、ドメイン代以外は基本的にかからない、と最初に伝える）

## 答えがあいまいなとき

- 「おまかせ」と言われたら、業種の一般的な構成で進め、最初のプレビューで確認してもらう
- 回答が止まったら、仮の内容で作り始め、プレビューに「仮」と分かる印を付けて見せる。文章や写真はあとから差し替えられることを伝える
