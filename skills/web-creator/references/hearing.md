# ヒアリング

サイトの目的と運用の仕方を、オーナーが選ぶだけで答えられる形で聞きます。聞いた内容は `SITE.md` の「概要」に書き残します。

## 聞き方の決まり

AskUserQuestion（選択肢つきの質問のツール）の上限に合わせます。ツールがない環境でも同じ形で聞きます。

- 1回に聞くのは4問まで。5問以上あるときは、4問ずつに分ける
- 1問の選択肢は4つまで。「その他」（自由に書ける欄）はツールが自動で付けるので、選択肢には入れない
- 質問の見出し（header）は12文字まで
- 複数を選んでよい質問は、複数選択（multiSelect）にする

出典: Claude Agent SDK のドキュメント「Handle approvals and user input」の Limitations（each AskUserQuestion call supports 1-4 questions with 2-4 options each）と Question format（header は12文字まで）。https://code.claude.com/docs/en/agent-sdk/user-input （2026-10-30 確認）

## 1回目（必須・4問）

| # | 質問 | 選択肢 | 何に使うか |
|---|---|---|---|
| 1 | サイトで一番してほしいことは？ | 問い合わせや予約 / 商品やお店を知ってもらう / 採用の応募 / 記事を読んでもらう | トップページの構成と、目立たせるボタン |
| 2 | 見てほしい人は？ | 取引先の担当者 / 近所のお客さん / 求職者 / 全国の読者 | 文章の口調、デザインの方向 |
| 3 | ページの数は？ | 1ページで十分 / 数ページ（会社概要、サービスなど）/ お知らせやブログもほしい / 記事をたくさん載せたい | ページの形（stack-selection.md の Q3）。「記事をたくさん」なら、2回目で記事の本数を聞く |
| 4 | 今サイトはありますか？ | ない / WordPress / STUDIO / ほかのサービス | 引っ越しの有無（migration.md） |

## 2回目（1回目の答えを見て、必要なものだけ4問ずつ）

| 質問 | 選択肢 | 何に使うか |
|---|---|---|
| ほしい機能は？（複数選択） | お問い合わせフォーム / 会員だけが見られるページ / 記事へのコメント欄 / ネットショップや予約の受付 | 対象外の判定（stack-selection.md の「対象外の判定」）。フォームなら下の「問い合わせの受け方」も聞く |
| 公開後、どのくらい更新しますか？ | ほぼしない / 月に数回 / 週に数回以上 / 毎日、複数人で | 更新の頼み方の説明（更新が多くても、それだけでは技術を変えない） |
| 記事は今、何本くらいありますか？（「記事をたくさん」のときだけ） | 100本未満 / 100〜999本 / 1,000〜2,999本 / 3,000本以上 | 対象外の判定（記事が数千本を超える見込み）。1年に増える本数もあわせて聞く |
| 雰囲気は？ | 信頼感 / 親しみ / 高級感 / にぎやか | デザイン案の方向。参考にしたいサイトの URL は「その他」に書いてもらう |
| ドメイン（example.co.jp のようなサイトの住所）は？ | 持っている / 持っていない / わからない | 持っていなければ、取得は後で一緒にやると伝える |
| 問い合わせの受け方は？ | Google フォームをリンクで開く（おすすめ）/ Google フォームをページに埋め込む / サイトと同じ見た目のフォーム / フォームは置かない | 選択肢の説明と、自前のフォームを選ぶ前に伝えることは forms.md |

選択肢では答えられないものは、質問のあとにチャットで頼みます。

- 素材: ロゴ、写真、会社案内の PDF、パンフレットがあれば添付してもらう。なければ「写真なしでも成り立つデザインにする」と伝える
- 掲載してはいけない情報: 個人の住所、未発表の情報など

## 3回目: 作業の環境（段階1の終わり、プロジェクトを作る前）

プロジェクトの指示（templates/project-instructions.md）を埋めるために聞きます。5問あるので、1〜4を1回目、5を2回目に分けて聞きます。

| # | 質問 | 選択肢 |
|---|---|---|
| 1 | ふだん使うパソコンは？ | Mac / Windows / パソコンは使わない |
| 2 | ふだん使うブラウザは？ | Chrome / Safari / Edge / わからない |
| 3 | 更新を頼むのは、主にどの端末から？ | パソコン / スマートフォン / 両方 |
| 4 | 原稿や写真は、どこに置くことが多い？ | チャットに添付 / Google ドライブ / Claude ドキュメント / 決めていない |
| 5 | 連絡がつきやすい時間は？ | 平日の日中 / 平日の夕方以降 / 土日 / いつでも |

Claude のデスクトップアプリや Claude in Chrome を入れているかは、質問せずに、使えるツールがあるかで確かめます。分からなければ「入れていない」として書き、入れると何が楽になるかを一文で伝えます。

## 対象外の要望が出たとき

会員機能、コメント機能、ネットショップ、決済、予約、記事が数千本を超えるメディアのどれかが必要と分かったら、stack-selection.md の「対象外の判定」に従い、その場で対象外であることと理由を伝えます。EC や予約が一部だけなら、外部のサービスへのリンクで済むかを提案し、サイトの残りの部分は進めてよいかを確認します。

## 受託制作だと分かったとき

依頼者が制作会社やフリーランスで、顧客のサイトを作ると分かったら、2回目で「公開後の記事の投稿は、だれが、どの方法で行いますか？」を聞きます（選択肢: 顧客が Claude に頼む / 制作者が代わりに投稿する / 顧客が AI を使わずに管理画面から投稿する）。最後の答えのときは、stack-selection.md の「受託制作のとき」に従い、対象外であることを伝えます。対象にする場合は、このときに LICENSE の受託制作の条件を一文で伝えます（お客さまのサイトにも使える。お客さまのリポジトリに skills/ を置けるのは、制作か保守を続けている間だけ。手を離すときは、お客さまが購入者でなければ skills/ を除く）。

## 聞かないこと

- 使いたい技術、サーバー、CMS の名前（エージェントが決める）
- 予算の細目（Claude の利用料と、ドメイン代以外は基本的にかからない、と最初に伝える）

## 答えがあいまいなとき

- 「おまかせ」と言われたら、業種の一般的な構成で進め、最初のプレビューで確認してもらう
- 回答が止まったら、仮の内容で作り始め、プレビューに「仮」と分かる印を付けて見せる。文章や写真はあとから差し替えられることを伝える
