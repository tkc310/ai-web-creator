# 公開前のプレビュー

サイトや記事を更新するときは、公開する前に、変更後のページを Claude のアーティファクト（HTML のページ）として見せます。オーナーはアーティファクトのカードを開くだけで、スマホと PC の両方の見え方を確認できます。スクリーンショットより、実際のページに近い状態で確かめられるためです。

## いつ見せるか

| 場面 | 見せるもの |
|---|---|
| 記事・お知らせの追加や修正 | その記事のページ |
| ページの文章や写真の修正 | 変更したページ |
| デザイン案の提示 | 案ごとのトップページ（タブで切り替え） |
| デザインの変更、ページ構成の変更 | 変更した主なページ（タブで切り替え） |
| 保守ルーティン、自動修正 | 見せない（見た目が変わらない更新のため） |

SITE.md で「確認なしで公開してよい」とされた種類の変更は、プレビューを作らずに公開してかまいません。ただし、要点から作った下書きは必ず見せます。

## 作り方

1. ビルドする（`npm run build`）。SSR のページや EmDash の場合は、`npm run preview`、`wrangler dev` など、ページを返すサーバーを起動する
2. scripts/make_preview.py で、ページを1つの HTML にまとめる

```bash
# ビルド結果から（HTML、Astro の SSG）
python3 <スキルの場所>/scripts/make_preview.py dist/news/2026-10-holiday/index.html --root dist \
  --out /tmp/preview/<サイト名>-preview.html --label "お知らせ「年末年始の休業」"

# 起動中のサーバーから（SSR、EmDash）
python3 <スキルの場所>/scripts/make_preview.py http://localhost:4321/news/2026-10-holiday/ \
  --out /tmp/preview/<サイト名>-preview.html --label "お知らせ「年末年始の休業」"

# 複数のページやデザイン案（タブで切り替え）
python3 <スキルの場所>/scripts/make_preview.py a/index.html b/index.html c/index.html --root . \
  --names "A案" "B案" "C案" --out /tmp/preview/<サイト名>-design.html --label "デザイン案"
```

スクリプトは、CSS、JavaScript、画像、フォントをページに埋め込み、ページを iframe に入れて、スマホ幅と PC 幅を切り替えられるようにします。サイト内のリンクは、プレビューの中では移動しません。外部から読み込むスクリプト（解析タグなど）は外します。

3. Artifact ツールで公開する（publish）。プレビューのファイルはリポジトリの外（作業用のフォルダ）に置き、サイトのリポジトリにはコミットしない
4. オーナーに、何を変えたかを1〜2行で伝え、「カードを開いて、スマホと PC の見え方を確認してください。よければ『OK』と返してください」と頼む
5. 直しの依頼があれば、直してプレビューを作り直し、同じアーティファクトに公開し直す（同じファイルのパスで publish すると URL が変わらない）

## プレビュー用のアーティファクトを使い回す

サイトごとにプレビュー用のアーティファクトを1つ決め、その URL を SITE.md の「プレビュー」に書きます。次からの更新では、その URL を指定して公開し直します（別の会話からは、先に Artifact ツールの read で読んでから publish する）。オーナーは、いつも同じ場所でプレビューを確認できます。

## 注意

- アーティファクトは、作った人だけが見られる状態で作られます。社内の人に確認してもらいたい場合は、オーナーがアーティファクトの共有メニューから共有します
- 公開前の情報（未発表の新商品など）を含むプレビューを、オーナーの了承なしに共有しない
- プレビューに、API トークンなどの秘密の値や、管理画面の情報を含めない
- アーティファクトを作れない環境では、スマホ幅と PC 幅のスクリーンショットを撮って見せる
- プレビューが 15MB を超える場合は、画像を縮小するか、ページを分けて作る
