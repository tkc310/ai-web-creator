# 既存サイトからの引っ越し

CMS（WordPress、Movable Type、Drupal など）や、ノーコードのサイト作成サービスからの引っ越しで読みます。目標は「検索順位と問い合わせを落とさずに乗り換えること」です。

## 1. 現状の棚卸し（エージェント）

1. 公開中のサイトのページを巡回し、URL、タイトル、見出し、本文、画像の一覧を作る（自社サイトであることをオーナーに確認してから行う）
2. 次のものを洗い出してオーナーに見せる
   - ページ数と記事数
   - フォーム、予約、会員機能、ショップなど「動く機能」
   - Googleアナリティクス、広告タグ、Search Console の有無
   - メールをドメインで使っているか（info@ドメイン など）
3. 動く機能ごとに「同じことを、どう実現するか」を決める（Googleフォーム、外部の予約サービスへのリンクなど）

## 2. コンテンツの取り出し

### WordPress

- オーナーに管理画面の「ツール → エクスポート → すべてのコンテンツ」でエクスポートファイル（XML）をダウンロードしてもらい、チャットに添付してもらう
- 画像は `wp-content/uploads/` の URL から取得する
- 記事を Markdown に変換し、frontmatter（title、date、description、image、tags）を付ける
- 記事が数百本以上あり、複数人が管理画面で書き続けたい場合は EmDash を検討する（stack-selection.md）。EmDash は WordPress のエクスポートファイルを取り込めます

### ノーコードのサイト作成サービスなど

- 公開ページを読み取り、文章と画像を取り出す
- サービスにエクスポート機能がある場合は、そちらを優先する。機能の有無はその時点のヘルプで確認する

## 3. URL を引き継ぐ（301 リダイレクト）

検索エンジンの評価を引き継ぐため、旧URLと新URLが変わる場合はすべて対応表を作ります。

```
# public/_redirects（Cloudflare Workers の静的アセットで使える）
/archives/123      /news/opening/         301
/company           /about/                301
/blog/:slug        /news/:slug/           301
```

- `_redirects` はクエリ文字列（`?p=123` のような部分）を条件にできません。WordPress の初期設定の URL（`/?p=123`）からの転送は、Cloudflare の Bulk Redirects か、転送用の小さな Worker で設定します。どちらにするかは件数を見て決め、設定前にオーナーに伝えます
- `_redirects` に書けるのは、固定の転送2,000件と、`:slug` などを使う転送100件までです。超える場合は Bulk Redirects を使います

- 旧URLと新URLが同じになるようにスラッグを合わせられるなら、合わせる方が確実です
- 対応表は `docs/redirects.csv` にも残す

## 4. 切り替え

1. 新しいサイトを workers.dev の URL で公開し、オーナーに全ページを確認してもらう
2. Lighthouse と構造化データを確認する（quality-gate.md）
3. オーナーの了承を得て、ドメインを新しいサイトに向ける（deploy-and-autofix.md の「独自ドメインの接続」）
4. 切り替え後1週間は旧サイトを残す。旧サービスの解約はオーナーが行う
5. Search Console でサイトマップを送り直し、404 エラーが増えていないかを1〜2週間確認する

## 5. 引っ越し後

- SITE.md に旧サービス名、切り替え日、リダイレクトの件数を書く
- 旧サイトにあった解析タグを新サイトにも入れるかをオーナーに確認する（入れるとパフォーマンスの点数が下がることがあるので、その影響も伝える）
