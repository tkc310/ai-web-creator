# 保守ルーティンの作り方

保守ルーティンは、Claude のスケジュールタスク（旧称: ルーティン）で動かします。スケジュールタスクは Anthropic のクラウドで動くので、オーナーのパソコンが閉じていても実行されます。Pro、Max、Team、Enterprise プランで使えます。

## 実行日

毎月1日と15日の 9:07（オーナーのタイムゾーン）に実行します。

```
7 9 1,15 * *
```

cron では「14日ごと」を正確に書けないため、月2回で2週間ごとに近い間隔にしています。ちょうど 9:00 にすると開始が遅れることがあるため、数分ずらしています。

## 作り方 A: エージェントが作る

会話の中でスケジュールタスクを作るツールが使える場合は、エージェントが作ります。作る前に、オーナーに次を伝えて了承を得ます。

- 毎月1日と15日に動くこと
- Claude の利用量を使うこと
- 実行の結果は Claude のスケジュールタスクの画面で見られること

設定する内容:

| 項目 | 値 |
|---|---|
| 名前 | `<サイト名> の保守` |
| プロンプト | routine-prompt.md の文章（`<...>` を埋める） |
| モデル | web-creator の references/versions.md のモデル（考える深さは site-maintenance スキルの設定で medium になる） |
| スケジュール | `7 9 1,15 * *`（オーナーのタイムゾーン） |
| リポジトリ | サイトのリポジトリ |
| 環境 | Default（npm のレジストリに接続でき、pnpm で依存パッケージを入れられる） |
| コネクタ | 不要なものは外す |

スケジュールタスクには、作るときに選ぶ承認の設定（permission mode）がありません。実行は auto mode で始まり、分類器が操作ごとに許すか止めるかを決めます。人が承認していないプルリクエストのマージは既定で止められ、同じ操作が続けて3回（合わせて20回）止められると、実行は確認を待って止まります。そのため、保守のプロンプトは、プルリクエストをマージせず、パッチとマイナーの更新だけを main に直接 push する形にしています（site-maintenance の「無人の実行で守ること」）。auto mode が使えない設定（組織で止めている、など）では、実行は始まったときの承認の設定のままになります（Claude Code のドキュメント「Scheduled tasks」の Permission prompts during a run、2026-10-30 確認: https://code.claude.com/docs/en/routines ）。

作成後、オーナーに次の2つを一文ずつ伝えます。

- 小さな更新は自動で反映し、大きな更新（メジャーの更新、公開の仕組みの部品）は、次に話すときに「OK」をもらってから反映する
- 実行が確認を待って止まっていたら、スケジュールタスクの画面の「History」からその実行を開くと、確認に答えられる（ふだんは見なくてよい。止まっていれば、次の会話で Claude から伝える）

## 作り方 B: オーナーが作る

スケジュールタスクを作るツールがない場合は、オーナーに次の手順を案内します。所要時間は10分くらいです。

1. claude.ai/code/routines を開き、「New task」を押す
2. 名前に `<サイト名> の保守` と入れる
3. プロンプトに、エージェントが用意した文章（routine-prompt.md を埋めたもの）を貼り、プロンプト欄のモデル選択で、web-creator の references/versions.md のモデルを選ぶ
4. トリガーで「Schedule」を選び、作成後の編集画面で「Custom」にして `7 9 1,15 * *` を入れる
5. 詳細設定でサイトのリポジトリを選び、環境は Default のままにする
6. コネクタの一覧から、使わないものを外す
7. 「Create」を押し、「Run now」で一度動かして、結果を確認する（実行のログに、main に入れたもの、残したプルリクエスト、止められた操作がないかを見る）

画面の名前は変わることがあるため、案内の前に Claude Code のドキュメント（スケジュールタスク）で最新の手順を確認します。

## スケジュールタスクを使えない場合

Claude 以外のエージェントなど、決まった日に自動で作業する機能がない場合は、毎月1日と15日にオーナーが「保守して」と頼む運用にします。オーナーのカレンダーに、繰り返しのリマインダーを設定するよう案内します。頼まれたら、site-maintenance スキルの「ルーティン1回分の手順」を行います。

## 注意

- スケジュールタスクは、オーナーの Claude アカウントと GitHub の接続で動きます。コミットとプルリクエストは、オーナーの GitHub ユーザーとして記録されます
- 指示がなければ、`claude/` で始まるブランチに push します。main に直接入れるのは、プロンプトに書いたパッチとマイナーの更新と、ログや SITE.md の記録だけです。GitHub のブランチの保護（branch protection）で main への push を止めていると、この push も止まるので、保守を設定したサイトでは main の保護に「直接の push を禁止」を入れません
- GitHub の接続が切れると、72時間は実行を見送り、それを過ぎるとタスクが止まります。止まっていたら、GitHub を接続し直してタスクを再開するようオーナーに伝えます
- 実行の状態が成功（緑）でも、作業がうまくいったとは限りません。ログ（logs/）で結果を確認します
